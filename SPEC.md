# Project spec (private prep) — job-application-tracker
Purpose: small FastAPI + SQLite API she can explain end to end; to be genuinely built by Codex (CLI/IDE/web) once her ChatGPT account route is confirmed. Spec is written so a coding agent can implement it directly.

## Stack
- Python 3.11+, FastAPI, uvicorn
- SQLite via stdlib sqlite3 or SQLModel (implementer's choice; no external services, no API keys)
- pytest + fastapi.testclient for tests

## Data model: applications
- id (int, pk), company (str, required), role (str, required)
- url (str, optional), source (str, optional, e.g. linkedin/referral/portal)
- status (enum: saved, applied, screening, interview, offer, rejected, withdrawn; default saved)
- applied_at (date, optional), notes (str, optional)
- created_at, updated_at (auto)

## Endpoints
- POST /applications -> 201, created record
- GET /applications -> list; query filters: status, company (substring, case-insensitive), applied_after, applied_before
- GET /applications/{id} -> 200 or 404
- PATCH /applications/{id} -> partial update; updates updated_at; 404 if missing
- DELETE /applications/{id} -> 204; 404 if missing
- GET /applications/export.csv -> text/csv of all records (header row), same filters as list
- GET /health -> {"status": "ok"}

## Validation/errors
- 422 on invalid status value or bad date format
- 404 JSON {"detail": ...} for missing ids

## Acceptance tests (pytest)
1. create application returns 201 with id and defaults (status=saved)
2. list returns created record
3. filter by status returns only matching records
4. filter by company substring is case-insensitive
5. applied_after/applied_before date range filters work
6. get missing id -> 404
7. patch updates fields and bumps updated_at
8. patch invalid status -> 422
9. delete -> 204 then get -> 404
10. export.csv returns header + rows, respects status filter
11. health endpoint ok
